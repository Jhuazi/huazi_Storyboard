# huazi_Storyboard（分镜图制作 SOP）

## Overview

本技能把"图生视频"项目的分镜图制作流程固化为可复用 SOP。核心原则：**所有空间逻辑必须在分镜图层面解决，不留给视频模型**——图都画不出来，视频大概率做不出来。

技能运行后的交付物是一个完整文件夹：

```
{名称}分镜图设定/            ← 自动创建于工作区或用户指定位置
├── 00_项目信息与素材清单.md
├── 01_空间物理规则总表.md
├── 02_分镜总表_shot表.md
├── 03_分段分镜图提示词.md    ← 核心：可直接复制投喂给画图模型的成品提示词
├── 04_验收与拼版清单.md
└── 05_视频环节提示词_五锁结构.md  ← 可直接复制投喂给视频模型的成品提示词
```

**铁律：输出文件中的所有提示词必须放在 fenced code block 中、完整自包含、可直接整段复制投喂给 AI 模型使用。** 禁止输出"请自行替换XX"式的半成品——所有变量（角色名、场景名、镜号内容）必须在生成时填好。需要留空的位置也必须显式写成「【在此填写角色A名称】」格式，让用户一眼知道填什么。

## 触发条件

用户出现以下任一意图时使用本技能：
- "给《XX》做分镜图 / 分镜脚本 / 分镜设定"
- "按SOP做第X章的分镜"
- "我想把小说改编成AI短剧，先做分镜"
- "做图生视频的前置方案"
- 明确提到"分镜图设定"文件夹

## 适用输入与最佳使用时机

**适用输入（任意小说均可，按实际拿到的东西适配处理深度）**：

| 拿到的输入 | 处理方式 |
|---|---|
| 章节正文（最常见） | 直接从正文提取场景、人物、对话、动作，拆 shot 表 |
| 章节大纲/故事梗概 | 先按大纲补写每镜的具体画面动作与情绪，再拆 shot 表；画面细节标注【依据大纲推演】 |
| 剧本/台词稿 | 直接按场景切分，对话戏优先设计正反打 |
| 人物卡/美术资产文件 | 直接引用为资产，标注"已有"；用户提供路径时先读取 |
| 什么设定都没有 | 先向用户确认人物清单、场景清单、画风基调，再开工 |

**最佳使用时机：拿到小说章节或大纲的那一刻即可使用，不需要任何前置准备。** 原因：
- 人物资产卡版面图、场景资产卡（主视角+锚点特写）、俯视图、场景变体的出图提示词由本技能产出（templates 1.1-1.6，每个资产含中文对照/英文/主形象纯图版/版面排版/反向五件套）——用户拿着提示词去画图模型生成即可，无需先自行生图
- 分镜拆解、剧本化的 shot 表由本技能从正文/大纲直接完成——无需先自行分镜或写分场剧本
- 用户若已有现成资产（人物卡、场景图、美术设定集），技能直接引用并跳过对应补全步骤

**不需要**：预先写好的分场剧本、预先生成的图片、特定平台账号。只需要：剧情文本 + 人物/场景的基本设定信息（没有则现场问）。

## 限制与边界

1. **本技能只产出文本提示词，不负责实际出图出片**——产出前**必须确认用户平台**（未指明则先询问）：豆包（默认主推：生图 Seedream 组图模式 + 视频 Seedance）、即梦、RunningHub（RHTV 无限画布/ComfyUI 工作流）、LiblibAI（多模型聚合/LoRA 训练）、本地 ComfyUI/MiniMax。各平台挂载数、拼版、视频语法差异见 `references/tool-adaptation.md`；流程总览见 `assets/技能使用流程图.svg`
2. **文字按工具分级规避**——豆包生图（Seedream 5.x）有可靠文字渲染，大字号短文字可尝试直出（验收不过再退回虚化），密集小文字仍一律虚化；ComfyUI/SD 系一律虚化；**视频环节任何工具都规避清晰文字**，靠后期字幕
3. **单条视频时长按豆包模型版本分档**——Seedance 2.0：单条 4-15s，多镜用**镜头编号式**（"镜头1：…"，2.0 不识别时间戳）；Seedance 2.5（专业版）：单条 4-30s，多镜用时间戳式（"0-5秒：…"）。对话戏一律一镜一条；ComfyUI/MiniMax 路径按 10-15 秒/段组织
4. **超长章节需分段处理**——单章超过约 60 秒成片量时，建议按场景切块分批产出，每批走完整六步
5. **同场角色参考图挂载数按豆包模型分档**——豆包生图：Seedream 5.0 lite/4.5/4.0 最多 14 张、其余版本最多 10 张；豆包视频：Seedance 2.0 图≤9+视频3+音频3、2.5 图≤30（实挂建议≤8 保稳）。挂载数充裕时可全员挂资产，物理规则仍需完整（挂图不豁免规则）；ComfyUI 路径：@图片1~3 最多挂 3 个角色+1 张场景图，其余角色写进物理规则作虚化背景。**例外（各路径通用）**：某角色是本段焦点却占不到参考位时，不得虚化——在物理规则中按其资产卡特征显式固定外貌并允许清晰呈现
6. **docx 输出依赖环境**——无文档转换能力时保留 .md
7. **空间锚定的前提是俯视图**——没有俯视图的复杂室内戏，穿帮风险显著上升，第 1 步会把俯视图列为最高优先级补全项

## 工作流（六步法）

### 第 0 步：确认输入与创建项目文件夹

0. **⚠ 平台确认（强制，先于一切产出）**：若用户未明确说明使用哪个生图/视频平台，**必须先询问**再产出提示词——"你用哪个平台出图和出片？豆包 / 即梦 / RunningHub / LiblibAI / 本地 ComfyUI，或其他？"。不同平台的挂载数量、拼版环节、视频提示词语法差异很大（见 references/tool-adaptation.md），问清后按对应路径产出；用户已明确平台时直接按该路径执行，不再追问。
0.5 **⚠ 风格确认（强制，与平台确认同批询问，先于一切产出）**：若用户未明确说明画风，**必须先询问**——"你要哪种画风？电影写实风 / 3D动漫风 / 3D真人风（写实CG）/ 2D动漫风 / 国漫风，或其他？"。确认后：①在 00 文件头部写"本资产风格声明"；②**所有资产卡、分镜图、视频提示词必须统一携带该风格的提示词**（风格词库见 references/prompt-templates.md 第六节，含各风格中英文投喂词与反向提示词）；③分镜任务指令中的"真人电影级别"字样按所选风格替换（如 3D动漫风 → "3D动漫风格电影级分镜图"）；④五锁结构 [STYLE LOCK] 首行即风格总述。**全项目风格不得混用**——资产卡与分镜/成片风格不一致会导致全部返工二次生成，这正是本规则要防止的。
1. 收集输入：小说/剧本名（用作文件夹名，即"某某"）、章节/剧情范围、人物清单、场景清单、原文或大纲。若用户提供项目文件路径，直接读取；若信息不足，先问清再动手。
2. 确定输出位置：用户指定了目录就用指定目录；否则用当前工作区根目录。
3. 运行脚本创建项目骨架：

```bash
python {skill_dir}/scripts/init_storyboard_project.py "某某" [--path 输出目录]
```

4. 若需 docx：默认输出 .md；仅当用户明确要求 docx 且环境中已有文档转换能力（如 docx 技能、pandoc）时才转换，转换失败则保留 .md 并说明原因。

### 第 1 步：素材清单（00 文件）

- 盘点 4 类前置资产：①人物资产卡版面图（每角色一张）②场景资产卡+俯视图 ③场景变体（如有）④剧情 shot 表素材
- 逐项标注资产状态：已有（给出来源路径）/ 缺失（给出补全用的可复制提示词）
- 缺失的场景/人物/道具资产，按 references/prompt-templates.md 第一节「资产卡版面规格模板库」（1.1 人物资产卡版面图 / 1.2 场景资产卡 / 1.3 场景变体 / 1.4 俯视图 / 1.5 室内三视图 / 1.6 道具资产卡）生成补全提示词。**每个资产提示词必须含五件套**：①中文对照提示词 ②英文投喂提示词 ③主形象/主视角纯图版 ④版面排版说明（区块比例+文字标注，最左上角资产代号）⑤反向提示词；**场景有变体时每个变体各写一条完整提示词**。出图顺序链：场景主视角 → 俯视图 → 反打/补充视角 → 人物资产卡
- 一章多场景时：每个场景各写一份物理规则块、各配一张俯视图；分镜段只引用该段所在场景的规则与俯视图
- 一场戏超过 3 个角色：只给有近景/互动的角色挂 @图片参考，其余写进物理规则作虚化背景；若某焦点角色占不到参考位，在物理规则中按资产卡特征显式固定其外貌并允许清晰呈现
- **资产命名与挂载对应（强制）**：每个资产分配唯一代号（人物 CH01-角色名；场景 S01-场景名-MV/TP/FP/RV/TD 与变体 -V1、-V2；道具 P01-道具名），出图文件名=代号；**00 文件末尾必须包含「资产命名与挂载对应表」**，逐个资产对应到 03 分镜提示词的 @图片N 槽位和 05 视频提示词的 @ref_image_N / 上传顺序；03、05 中引用资产时也使用同一代号，三处名称完全一致
- **虚化分镜的"视频随机脸"预防**：分镜虚化不等于视频里该出现随机清晰脸。凡是虚化人群会出现在视频可辨识焦段的镜头（近景/特写/人物抬头动作），必须同步在 shot 描述与物理规则中约束面部呈现方式（低头/扶额/面部朝向桌面/景深外/不正脸直视镜头），确保脸的首次清晰建立只发生在挂参考图或显式固定外貌的镜头；全景中随机脸仅几十像素不可辨识，无需处理。验收清单须加"虚化人群镜头无人正脸直视镜头"检查项

### 第 2 步：空间物理规则总表（01 文件）

为每个场景写一份"场景宪法"，这是防穿帮的根基，后续所有提示词都会引用它。必含 8 项：空间尺寸与布局、每人初始位置与姿态、朝向与相对关系、互动触发顺序、人物数量上限、避免同框约束、AI 难生成画面规避项（文字密集区虚化规则等）、负面要求（无字幕无水印）。

规则措辞必须可直接嵌入提示词（参照模板中的句式），写成后同样放 fenced code block。

### 第 3 步：拆 shot 表（02 文件）

把剧情拆成总 shot 表，每镜 5 要素：**时长 / 景别 / 运镜 / 情节描述 / 情绪**，外加**节奏标注列（爆点/爽点/反转/铺垫/钩子）**。按约 10 秒/段 × 4 镜/段组织为"段"，总时长按剧情密度定（一般一章 ≈ 40-60 秒）。对话文戏必须设计正反打镜头并锚定双方站位。

**节奏与钩子规则（强制）**：
1. **每集最后一镜必须是钩子帧**——悬念/反转/危机未解的定格画面（如关键道具落到桌上、某人说出反常识台词、面具转向镜头），钩子帧不揭示答案
2. **爆点**（强冲突/处决/嘶吼等）放在段尾而非段首，铺垫镜头在前；全章至少 1 个爆点
3. **爽点**（主角智斗得逞、预言应验、打脸）紧跟在压抑铺垫之后释放；无爽点的纯铺垫章须在钩子中预埋爽点期待
4. **反转**：在 shot 表中提前一镜埋"可回看的伏笔画面"（如空椅子的特写），反转揭示镜头直接回扣该画面
5. 节奏标注写入 02 表并同步反映到 03 分镜提示词的 shot 描述与 04 验收清单（验收时检查"铺垫镜在前、爆点在后、钩子定格收尾"）

### 第 4 步：分段分镜图提示词（03 文件，核心交付）

每段生成一条**完整成品提示词**，结构 = 任务指令 + @图片分工 + 本段物理规则（共用规则+段特化）+ shot 表 + 负面要求。全部变量填好，fenced code block 包裹，标注"@图片N 应挂载的资产"。

模板与句式见 references/prompt-templates.md；完整实战示例见 references/example-chapter.md。

### 第 5 步：验收与拼版清单（04 文件）

- 逐段验收清单：人数对、位置对、大小对、结构对、无字幕五项 + 本项目特有锚点项（如零号牌位置、座位关系、贯穿道具）
- 翻车修复对照表：现象→原因→修复（改物理规则重生成，**不抽卡**）
- 拼版说明：四宫格→裁剪→九宫格；空间锚定图挂载策略（人物落座后全程挂俯视图）。**工具差异**：豆包/即梦用组图模式一次产出 4 张连贯独立图时，裁剪与九宫格拼版环节省略，04 文件仍照常产出（验收清单照用）

### 第 6 步：视频环节提示词（05 文件）

为每段产出**五锁结构视频提示词成品**：`[项目规格] → [STYLE LOCK] → [REFERENCE LOCK] → [PHYSICAL / CONTINUITY LOCK] → [SHOT 01~N]`（逐镜含口型同步台词、焦段、结束画面定格）`→ [AUDIO LOCK]`（分时段音效、无旁白声明）。每镜用 HARD CUT 分隔。同样直接可复制投喂。

## 质量红线

1. 所有提示词成品化——用户应能复制粘贴直接用，无需任何改写
2. 人物数量、空间大小、位置关系必须显式写进提示词——不写必穿帮
3. 文字密集画面（招牌、号码牌、规则卡、弹幕、屏幕文字）一律写虚化规则，文字由后期字幕补
4. 贯穿全剧的道具与外观锚点（如主角的表、标志服装）写入每段物理规则
5. 分镜与剧情一一对应：每镜都能在原文中找到依据，不无中生有
6. 不合格的分镜靠改物理规则重生成，不建议抽卡
7. **资产提示词五件套齐全**——中文对照/英文投喂/主形象纯图版/版面排版/反向提示词缺一不可；场景变体逐个写完整提示词；资产卡版面各区块比例与文字标注（最左上角资产代号）必须显式写入提示词
8. **命名三处对应**——资产代号 ↔ 03 分镜 @图片N ↔ 05 视频 @ref_image_N 完全一致，00 文件必须有对应表；对不上即返工
9. **资产卡背景浅色**——人物/道具资产卡背景统一纯白或浅灰最佳，禁用深色背景；场景资产卡版面底色浅灰
10. **每集必有钩子**——每集最后一镜必须是钩子帧；shot 表必须有节奏标注（爆点/爽点/反转/铺垫/钩子），爆点放段尾、爽点紧跟压抑铺垫、反转提前埋可回看伏笔
11. **风格前置确认且全链路一致**——动手前未确认风格必先问（电影写实/3D动漫/3D真人/2D动漫/国漫等）；确认后所有资产卡/分镜/视频提示词统一携带该风格词（词库见 prompt-templates 第六节），全项目不得混用，防止弄错风格二次生成
